# ThreatLens 계획 설계서 (plan.md)

버전: 최신판 · 작성 2026-10-06 · 작성자 정환주 (구현은 Claude에게 위임, 판단·확인은 본인)

## 0. 목표 입력 4칸 (붙여 넣기용)

**한 줄 소개**
AI 서비스 구조를 그리면 공격 경로와 먼저 막을 일을 알려 주는, 서버·AI 호출이 없는 무료 브라우저 도구입니다.

**누구를 위한 것인가**
보안 전문가 없이 AI 서비스를 만드는 기획자·개발자, 그리고 AI를 설비·공정 시스템에 연결하려는 공정 엔지니어.

**핵심 기능 3가지**
1. 질문 8개 또는 캔버스로 AI 서비스 구조도 만들기
2. 규칙 40개(근거 표기)로 공격 경로 찾기 + 위협별 3줄 시나리오와 점수
3. 먼저 할 대응 순서(행동 계획)와 점수 변화 미리보기, A4 보고서 내보내기

**완성의 기준**
- 예시 5종(문서 Q&A, 고객상담, 코드 에이전트, 메일 비서, 공정 운전 보조)을 불러오면 점수·위협·행동 계획이 모두 나온다.
- 처음 쓰는 사람이 질문 8개에 답하면 60초 안에 구조·점수·행동 계획이 나온다.
- 규칙 40개 모두 공개 표준 근거가 표기되어 있고, 정답표 대비 재현율과 한계를 숨기지 않고 공개한다.
- 자동 시험(단위 800개, 브라우저 76개)과 lint·타입·빌드가 통과하고, 배포 주소가 열린다.
- 5명 사용성 테스트에서 과제 완료율 80% 이상, 과제 1 소요 90초 이내, 평균 만족도 4 이상 (현재 준비만 끝남, 미실시).

---

## 1. 배경과 문제
AI 서비스를 만드는 사람은 "우리 구조 어디가 위험하고 무엇부터 고칠지" 알 방법이 마땅치 않습니다. 보안 컨설팅은 비싸고 느립니다. 서비스 구조를 외부 서버에 올리는 도구는 구조 자체가 민감해서 쓰기 어렵습니다.

## 2. 제약 (본인이 정한 것)
- 유료 비용 없음, AI 호출 없음: 모든 판정은 브라우저 안의 규칙 엔진으로 재현됩니다.
- AI 보안 주제, 남들이 흔히 만들지 않는 주제, 체크리스트가 아닌 서비스 수준의 품질.
- 화공 설비·공정 특화 규칙 포함.
- 구현·문서는 Claude가 하고 본인은 지시와 결과 확인을 맡는다.

## 3. 범위
**포함**: 구조도 편집기(부품 20, 속성 18), 질문 마법사, 규칙 40개, 점수, 행동 계획, 구조 점검, 보고서, 공유·저장, 평가표.
**제외**: 실시간 취약점 스캔, 로그인·서버 저장, AI 모델로 위협 생성, 법적 인증 대체, 모바일 앱.

## 4. 동작 원리
- 구조도를 그래프로 보고, AI 노드마다 자신과 이웃 노드의 속성을 모아 규칙 조건과 맞춥니다. 신뢰 경계(사내/사외)를 넘는 화살표는 엔진이 자동 계산합니다.
- 점수는 AI 노드별 `100×(1−Π(1−위험))`, 전체는 최댓값입니다. 대응을 적용하면 해당 위험이 줄고 바닥값 10%는 남습니다.
- 행동 계획은 난이도를 반영해 "다음 한 개"를 반복 선택합니다.
- 기술: React 19, Vite, TypeScript, React Flow 12. 배포는 정적 파일(서버 없음).

## 5. 진행 점검 5단계와 현황

| 단계 | 내용 | 상태 |
|---|---|---|
| 목표 확정 | 주제 ThreatLens 확정, 화면 시안 2장 승인 | 완료 |
| 계획 v1 업로드 | 이 문서의 이전 판 | 완료 |
| 중간 점검 1차 | 캔버스, 규칙, 점수, 근거 링크, 평가표 | 완료 |
| 중간 점검 2차 | 디자인 시스템 교체, 행동 계획, 3줄 시나리오, 질문 마법사, 구조 점검 | 완료 |
| 최종 제출 | 규칙 28→40개, 신뢰 경계, 보고서 v2, 문서화, 배포 | 준비 완료 (제출 대기) |

## 6. 바뀐 점과 그 이유 (주제 변경 없음)
- 점수만 보여 주던 화면에 **행동 계획**을 넣었습니다. 이유: "그래서 무엇부터 고치나"에 답해야 쓸모가 생깁니다.
- **질문 8개 마법사**를 넣었습니다. 이유: 빈 캔버스에서 시작하는 장벽이 가장 컸습니다.
- 규칙을 28개에서 40개로, **신뢰 경계**를 추가했습니다. 이유: 사내/사외를 넘는 데이터 흐름이 핵심 위험이기 때문입니다. 대가로 경고 적중률이 91%에서 84%로 내려갔고 이를 그대로 공개했습니다.
- **보고서 v2**(표제란, 구조 도면, A4 인쇄)를 만들었습니다. 이유: 제출·공유용 문서가 필요했습니다.

## 8. 위험과 대응
- 규칙·시나리오를 AI가 작성해 틀린 표현이 섞일 수 있습니다 → 근거 링크 대조, 정답표 독립 유지, 별도 검수 에이전트의 교차검증, 한계 공개. **사람 전문가 검수는 아직 안 했고** 앱·보고서에 "사람 전문가 검수 전"을 표기했습니다.
- 신뢰 경계 규칙 4개(R-35~37, R-39)는 예시 5종에서 발동하지 않아 평가하지 못했습니다 → 정답표 확장 필요.
