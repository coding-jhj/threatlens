## 2. 독립 검수 결과와 반영

검수자는 규칙 파일을 쓰지 않은 별도 에이전트입니다(전문가가 아니라 AI이므로, 아래 "사람이 해야 하는 일"을 대체하지 않습니다).

**반영함**
- 과장 문구 완화: R-03(시스템 전체→연쇄적 변경), R-07, R-17, R-18(가장 넓습니다→넓습니다)
- 조건으로 알 수 없는 전제를 문장에서 "~라면"으로 조건화: R-14, R-16, R-19, R-20, R-23, R-26(1행)
- 점수 과대 조정: R-01·R-14 출처 구분, R-03 샌드박스, R-09·R-13 범위 검사(난이도 보통으로), R-14 출력 필터, R-20 업체 옵션, R-22 수신자 허용 목록, R-25(승인 -20, 샌드박스 -30)
- 대응 교체·추가: R-23 `쓰기 시 권한 구분` → `검색 시 질문자 권한으로 거르기`, 설비 규칙에 `AI는 권고만 하고 제어 쓰기 경로 제거`(R-10·R-12·R-13), `중복 센서·물리 모델과 교차 검증`(R-09), R-13에 담당자 확인
- 근거 정정: R-27 근거를 LLM03 → LLM05(출력 처리)로, R-06에서 주제가 어긋난 ATLAS T0057 제거
- 겹치는 대응의 합이 커지지 않도록 설비 규칙 대응 점수 합을 90 이하로 조정(기존 시험이 요구)

**반영하지 않음 (구조 변경이 필요하거나 판단이 갈림)**

| 지적 | 이유 / 상태 |
|---|---|
| `human.approval` 속성 하나를 모든 승인 대응이 공유(저장소 검수가 설비 승인을 대신함) | 속성 분리는 엔진·화면·평가표 전체 변경. 한계로 남김. 평가표 정답과 함께 G6에서 재검토 |
| 대응 점수 단순 합산(겹침 과대평가) | 이미 하한 10%와 규칙별 합 상한 시험이 있음. 화면에 "추정치" 표시는 G7 보고서에 추가 예정 |
| 포함 관계 규칙(R-01⊂R-02 등) 이중 계산 | 점수는 위협별 위험을 곱으로 합쳐 이미 포화됨. 접기(`supersedes`)는 G6 후보 |
| R-26 심각도 낮추기 | 평가표 결과가 바뀜. 사람 검토 항목으로 이관 |
| 대응이 `when` 조건을 지우지 못함(`sets`만 있음) | 의도한 설계: 점수는 낮추지만 위협은 계속 표시함(남은 위험 10% 하한) |
| `memory.recall`, `store.per_user` 속성 추가 | G6(속성 +4) 후보 |
| MITRE ATLAS 번호·ATT&CK for ICS 번호 일부, CISA 지침 원문, IEC 61511 원문 | 검수자와 작성자 모두 원문 확인 불가. 아래 사람 확인 항목 |

## 3. 가중치 민감도 결과

예시 5개(문서 질의응답 / 고객지원 / 코드 에이전트 / 메일 비서 / 공정) 점수:

| 흔든 값 | 예시 5개 점수 | 결과 |
|---|---|---|
| 기준 | 25 / 63 / 61 / 51 / 43 | - |
| 심각도 전체 ×0.7 | 18 / 50 / 48 / 38 / 32 | 같음 |
| 심각도 전체 ×0.85 | 22 / 57 / 55 / 45 / 38 | 같음 |
| 심각도 전체 ×1.15 | 29 / 69 / 66 / 56 / 48 | 같음 |
| 심각도 전체 ×1.3 | 32 / 73 / 71 / 61 / 53 | 같음 |
| high ×0.7 | 25 / 57 / 52 / 42 / 33 | 같음 |
| high ×1.3 | 25 / 69 / 69 / 58 / 51 | 같음 |
| medium ×0.7 | 18 / 57 / 57 / 47 / 42 | 같음 |
| medium ×1.3 | 32 / 69 / 64 / 54 / 44 | 같음 |
| low ×0.7 | 25 / 63 / 61 / 51 / 43 | 같음 |
| low ×1.3 | 25 / 63 / 61 / 51 / 43 | 같음 |
| 난이도 1/1/1 (무시) | 계획이 달라진 예시 4/5, 난이도 반영의 점수 손해 1/2/0/2/0점 | - |
| 난이도 1/1.5/2 | 첫 추천 5/5 동일 | - |
| 난이도 1/3/5 | 첫 추천 5/5 동일 | - |

읽는 법: 어떤 가중치를 흔들어도 예시들의 위험 **순서**는 같습니다. 숫자 자체는 바뀝니다(예: 심각도 전체 ×1.3이면 메일 비서 51→61). 그래서 점수는 "절대 확률"이 아니라 "구조끼리 비교하는 지표"로만 설명합니다.

## 4. 사람 시험을 AI가 대신한 부분과 남은 부분

"AI 교차검증"은 사람 검증이 아닙니다. 같은 계열 모델의 편향을 공유할 수 있으므로 표기를 분리합니다.

| # | 사람이 할 일 | AI가 대신한 것 | 결과 | 아직 사람이 해야 하는 것 |
|---|---|---|---|---|
| H1 | 전문가 규칙 검토 | 보안 검수 에이전트(위 2) + 공정안전 관점 에이전트가 R-09~R-13 검토 | 공정안전 검수: SIS를 "막는 장치"로 쓴 문구, SIS가 있다는 과신, 같은 센서를 쓰는 인터록, 승인을 보호 계층으로 오해 등을 지적 → 문구 반영(R-09~R-13, 속성 `interlock.external` 이름·설명) | 실제 전문가 1명의 확인. IEC 61511 조항·SIL·LOPA 관련 주장은 검수자도 "확인 불가" |
| H2 | 평가표 정답 사람 검수 | 블라인드 재작성 후, **AI 판정자 3명이 따로** 부분 일치 4건과 보충 13건을 판정(다수결, `docs/eval/blind-recheck.md`) | 부분 일치: P1·P2 다른 위협, P3-a 렌더링 유출 다른 위협(mail-X7과 동일), P3-b·P4 같은 위협. 보충 13건 중 5건 추가(doc-qa-X1·X2, support-X3, code-X5, mail-X7), 8건 제외. P1·P2 포함 보충 7개를 `ground-truth-additions.json`에 분리(기존 정답 불변). **v2 재현율 느슨 69%(25/36), 엄격 53%(19/36)**, v1은 72%/52% 그대로 | 사람 전문가의 판정. 판정자는 모두 같은 계열 AI라 같은 편향을 공유할 수 있음 |
| H3 | 실제 스크린리더 시험 | 접근성 트리 덤프를 읽는 **NVDA 탐색 모드 시뮬레이션 에이전트**(개선 전·후 2회) + 키보드 흐름 자동 시험 | 개선 전 T5(구조 파악) FAIL 등 21개 지적 → 연결선·부품 한국어 이름, 연결 목록, 제목 구조(h1/h2), 점수 변화 상태 안내와 포커스 이동, 숫자 노이즈 제거, 마름모 중복 제거, 한국어 컨트롤 이름, 카드·접기 aria-controls, 화면 전환 제목, 평가표 caption·용어 설명 반영. 개선 후 6과제 중 5 PASS, 나머지 1은 덤프로 확인 불가(위협 카드 펼친 내용) | 실제 NVDA/VoiceOver 소리 시험. 시뮬레이션이 못 본 항목: 대화상자 포커스 가둠, 캔버스 안 키보드 조작 실제 동작, 안내 방송 여부 |
| H4 | 사용자 시험 5명 | **가상 사용자 에이전트 3명씩 2회**(PM·화공 전공자·개발 입문 학생, 같은 9문항) + 처음 방문자 흐름 자동 시험 | 개선 전: 점수가 확률인가(Q5)·실제 안전해졌나(Q7)·누가 썼나(Q8)가 "화면에서 알 수 없음". 개선 후 3명 모두 Q5·Q7 정확히 답함, Q8은 행동 계획 탭과 평가표에서 답함. 남은 혼란: R-02 풀이, 용어(프롬프트 주입, HAZOP 등), 점수 계산식, AI 작성 고지가 첫 화면·지도 본체에는 없음 | 실제 5명. 에이전트는 "화면 텍스트 이해"만 재며 감정·망설임·조작 실수는 못 잼 |
| H5 | 외부 출처 원문 확인 | 웹에서 OWASP·ATT&CK ICS·CISA·ATLAS·IEC를 직접 열어 대조(2회) | OWASP 7개, ATT&CK ICS 4개, CISA 3개 확인. **오류 발견·수정**: ATLAS 개별 기법 URL이 404라 atlas-data CHANGELOG·ATLAS.yaml로 교체, T0085.000 상위 이름(Data from AI Services)·T0086(v5.0.0)·T0101(v5.2.0) 도입 버전 표기, T0080 하위 번호 미확정이라 상위만 표기, CISA 제목·날짜·ic3.gov PDF·cyber.gov.au 보조, IEC는 "whenever possible" 권고로만 표기(조항 번호 삭제) | 열리지 않은 곳: atlas.mitre.org 기법 페이지(404), cisa.gov(403), IEC 원문(유료). 요약 모델을 거친 확인이라 인용문이 원문과 100% 같다고 보장 못 함 |

### 반영하지 않은 공정안전 지적

- SIS 설정값·바이패스 쓰기 차단, MOC, 단방향 전송(데이터 다이오드)을 새 대응으로 추가: R-10·R-12·R-13의 대응 점수 합이 이미 상한 90이라 점수 재조정이 필요 → G6에서 규칙 추가와 함께 처리
- 같은 대응 `human_confirm`의 점수가 규칙마다 다른 것(-10~-25): 승인이 유일한 통제인 규칙은 높게 둔 의도적 차이이나, 근거가 약하므로 사람 검토 항목
- 결과 화면에 "HAZOP/LOPA·SIL 검증·MOC를 대체하지 않습니다" 고정 문구: G7(보고서 v2)에서 추가
- `safe_state` 대응 id 이름 변경(IEC의 '안전 상태'와 혼동): 라벨만 고치고 id는 유지

## 5. 출처 표기

- 규칙 문구·시나리오·난이도·대응 점수·평가표 정답은 AI가 작성했고 AI 교차검증(별도 에이전트 3종 + 원문 대조)까지 거쳤으나 **사람 검수 전** 상태입니다.
- 이 도구는 보안·AI 위험 점검용 참고 지표이며 HAZOP/LOPA, SIL 검증, IEC 61511 적합성 평가, 변경관리(MOC)를 대체하지 않습니다.
- 점수는 추정치이며 실제 사고 확률이 아닙니다.
