## 방법과 한계 (먼저 밝힙니다)

- **본 제출은 이 결과를 plan.md의 사용성 검증 항목으로 채택했습니다** — 실제 사람 5명 테스트가 아니라 AI 에이전트 1회 조작으로 대체한다는 결정은 작성자(정환주)가 내렸고, 위 한계를 숨기지 않고 공개합니다.

### 객관적 확인 사실 (1회 실측)

1. **과제 1**: 질문 8개에 순서대로 답(외부인 질문 예·외부 파일 읽음 예·고객정보 접근 예·메일 발송 예·코드 실행 아니오·사람 승인 아니오·화공 설비 아니오·독립 인터록 아니오) → "구조가 만들어졌습니다. 부품 7개, 연결 6개... 위험 점수는 55점" 모달이 뜸. 메일 비서 예시의 점수(55)와 정확히 일치 → **완료**. 모달에 "(0~100 참고 지표)"라는 설명이 상시 노출되어 있음을 확인 — 10/20 개선사항이 실제로 반영돼 있었습니다.
2. **과제 2**: 도면 화면을 열자 우측 "발견된 위협 8개" 패널에 "가장 먼저 막을 위험"으로 R-01이 자동으로 펼쳐져 있고, 원인("공격자가 외부 문서에 사람 눈에 잘 띄지 않는 명령을 적어 둡니다")→AI가 하는 일→결과 3줄이 클릭 없이 바로 보임 → **완료**.
3. **과제 3**: "지금 할 일 3개" 중 1번 "전송 전 사람 승인 단계 추가"의 [적용] 클릭 → 점수가 **55 → 35로 실제 하락**(-20) → **완료**.

세 과제 모두 완료(3/3), confused_count는 아래 발견 1건으로 1회 추가.

### 새로 확인한 UX 위험 (전 세션에서 관찰만 하고 미기록이었던 건)

**"예시 카드 vs 질문 마법사" 혼동 위험 — 실측으로 재현**

빈 캔버스 화면의 "부품을 끌어다 놓아 보세요" 안내 패널에는 "질문 8개로 시작" 버튼과 5개 예시 카드(사내 문서 QA 봇·고객상담 챗봇·코드 에이전트·메일 비서·공정 운전 보조)가 **같은 패널 안에 함께** 표시되며, 카드 쪽이 오히려 화면 면적을 더 많이 차지합니다. 상단 툴바의 "예시 불러오기" 버튼과는 별개로, 이 카드 자체를 클릭해도 **확인 절차 없이 즉시** 해당 예시가 전체 캔버스에 로드된다는 것을 재현 확인했습니다(빈 캔버스에서 "메일 비서" 카드를 1번 클릭 → 즉시 점수 55점짜리 구조로 교체).

- 위험 시나리오: "예시 불러오기는 쓰지 마세요"라는 지시를 받은 사용자가 "질문 8개로 시작" 버튼을 찾으려다, 패널 안의 예시 카드를 "질문 항목 목록"으로 착각해 클릭할 가능성이 있습니다. 카드와 버튼이 같은 패널 안에 있고 카드가 더 크고 많기 때문입니다.
- 이번 1회 조작에서는 실제로 혼동 없이 버튼을 정확히 클릭해 과제를 완료했지만(사람처럼 망설이거나 오클릭하는 과정은 AI 조작으로 측정 불가 — 기존 한계와 동일), 카드 클릭의 즉시성·되돌리기 난이도는 실측으로 확인된 사실입니다.
- **권고(아직 미반영)**: 예시 카드 클릭 시 "이 예시를 불러올까요?" 같은 1차 확인을 넣거나, 카드 영역과 마법사 버튼의 시각적 위계를 더 분리하는 안을 다음 개선 후보로 남깁니다. 이번 제출에서는 시간 관계상 코드에 반영하지 않았습니다.
