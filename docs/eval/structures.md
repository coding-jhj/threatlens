# 평가용 참조 구조 5개

ThreatLens가 얼마나 위협을 잘 찾는지 재기 위한 **대표 서비스 구조**입니다. 앱의 "예시 불러오기"와 같은 구조(`src/samples/samples.ts`)를 씁니다.
화살표는 **정보·명령이 흐르는 방향**입니다. 괄호는 부품에 체크한 속성입니다.

## 1. 사내 문서 질의응답 봇 (`doc-qa`)
직원 질문과 업로드 문서를 바탕으로 사내 문서 저장소에서 답을 찾습니다.
- 부품: 업로드 문서(믿을 수 없는 입력) · 사용자 · AI 에이전트(민감정보) · 문서 저장소 · 대화 로그(로그 저장)
- 연결: 업로드 문서 → AI, 사용자 → AI, 문서 저장소 → AI, AI → 대화 로그
- 도구(메일·코드 실행 등)가 없는 **읽기 중심** 구조입니다. 위협은 주로 "읽은 것을 어떻게 다루는가"에서 나옵니다.

## 2. 고객상담 챗봇 (`support-bot`)
회사 밖 고객의 말을 받아 주문 조회 API를 호출하고 대화를 저장합니다.
- 부품: 사용자=고객(믿을 수 없는 입력) · AI 에이전트(민감정보, 외부 업체 모델 사용) · 외부 API(외부로 보냄) · 대화 로그(로그 저장) · 문서 저장소(FAQ)
- 연결: 고객 → AI, 문서 저장소 → AI, AI → 외부 API, AI → 대화 로그
- **불특정 다수가 입력**하고, 고객 정보가 외부 업체 모델·외부 API를 지나는 구조입니다.

## 3. 코드 에이전트 (`code-agent`)
웹 문서를 읽고 코드를 직접 실행하며 저장소에 씁니다.
- 부품: 웹 페이지(믿을 수 없는 입력) · 사용자(개발자) · AI 에이전트(쓰기 권한, 저장소 쓰기) · 코드 실행(코드 실행) · 문서 저장소 · 외부 API(외부로 보냄)
- 연결: 웹 페이지 → AI, 개발자 → AI, AI → 코드 실행, AI → 문서 저장소, 코드 실행 → 외부 API
- **실행 권한이 큰** 구조입니다. 읽은 내용이 곧 실행으로 이어질 수 있습니다.

## 4. 메일 비서 (`mail-assistant`)
받은 메일을 읽고 연락처를 참고해 답장을 직접 보냅니다.
- 부품: 업로드 문서=받은 메일(믿을 수 없는 입력) · AI 에이전트(민감정보) · 문서 저장소(연락처) · 메일 전송(외부로 보냄) · 외부 수신자
- 연결: 받은 메일 → AI, 연락처 → AI, AI → 메일 전송, 메일 전송 → 외부 수신자
- "입력 → AI → 밖으로 보냄"이 한 줄로 이어지는 **대표적인 유출 경로**입니다.

## 5. 공정 운전 보조 (`process-assistant`) — 화공
반응기 센서 값을 읽고 운전원에게 조언하며 제어 API까지 호출합니다.
- 부품: 센서 값(센서 입력) · 사용자=운전원 · AI 에이전트 · 제어 API(쓰기 권한, 설비 제어) · PLC·DCS · 대화 로그(로그 저장)
- 연결: 센서 → AI, 운전원 → AI, AI → 제어 API, 제어 API → PLC, AI → 대화 로그
- AI와 설비 사이에 **독립 안전 인터록이 없는** 구조입니다 (속성 "안전 인터록이 AI 밖에 독립 존재"를 체크하지 않음).

## 한계
- 5개는 대표 예시일 뿐 모든 서비스를 대표하지 않습니다.
- 구조는 사람이 정한 것이라, 정답 위협 목록(E2)이 같은 구조를 보고 작성되어도 편향이 있을 수 있습니다.
