# 사용성 테스트 진행 스크립트 (5명, 1명당 15분)

준비물: 노트북 1대(브라우저로 배포 주소 열기), 휴대폰 타이머, 기록표(`record-sheet.csv`), 이 스크립트.
관찰자는 **도와주지 않고 지켜보기만** 합니다. 막혀도 힌트를 주지 말고, 30초 이상 멈추면 "지금 어디가 막혔나요?"만 묻습니다.

## 1. 환영 (2분)
읽어 주기:
> 이 도구는 AI 서비스를 도면처럼 그려서 어떤 보안 위험이 있는지 보여 줍니다. 여러분을 시험하는 게 아니라 도구를 시험하는 것입니다. 틀려도 괜찮고, 막히는 곳이 있다면 도구의 문제입니다. 생각나는 대로 말씀해 주세요.

확인: 이름은 기록표에 P1~P5로만 적습니다(실명 기록 안 함). 화면 녹화는 하지 않고 관찰 메모만 합니다. 참여 동의를 말로 받습니다.

## 2. 과제 (각 3~4분, 합계 약 8분)
시작 화면(빈 캔버스)에서 출발합니다. 과제 문장은 그대로 읽어 줍니다.

| 과제 | 읽어 줄 문장 | 완료 기준 | 기록 |
|---|---|---|---|
| 1. 질문으로 구조 만들기 | "지금부터 '메일을 읽고 답장을 보내 주는 AI 비서'를 도구로 그려 보세요. 예시 불러오기는 쓰지 마세요." | 위험 점수가 화면에 나온다 | 시작~완료 초(타이머), 막힌 곳 |
| 2. 가장 큰 위험 말하기 | "이 구조에서 가장 큰 위험이 무엇인지 말로 설명해 보세요." | 위협 하나를 골라 원인→결과를 자기 말로 설명 | 완료 여부, "무슨 뜻인지 모르겠다" 횟수 |
| 3. 대응 적용해 점수 낮추기 | "점수를 낮춰 보세요." | 대응을 적용해 점수가 내려간다 | 완료 여부, 막힌 곳 |

관찰 포인트(메모): 질문 마법사를 찾았는가, 부품을 직접 놓았는가, 연결(화살표) 방향을 헷갈렸는가, 행동 계획 탭을 열었는가, 용어(예: 신뢰 경계, 인터록)에서 멈췄는가.

## 3. 소감 (5분)
1. "가장 헷갈린 곳은 어디였나요?"
2. "이 점수를 믿을 수 있을 것 같나요? 왜요?"
3. "누군가에게 쓰라고 권하겠습니까?"
4. 한 줄 만족도: "전체적으로 쓰기 쉬웠다 (1 전혀 아니다 ~ 5 매우 그렇다)" → 숫자만 기록.

## 4. 기록 규칙
- `t1_sec`은 과제 1 시작부터 점수가 나올 때까지 초. 못 끝냈으면 비워 두고 `t1_done=0`.
- `confused_count`는 "이게 무슨 뜻인지 모르겠다"고 말하거나 용어 설명을 찾아본 횟수의 합.
- `stuck_where`는 막힌 화면·버튼 이름 한 줄(없으면 비움). 쉼표 대신 `;` 사용.
- 5명을 모두 마친 뒤 `node scripts/summarize-usertest.mjs 기록표.csv`로 집계합니다.

## 5. 목표 (미달이면 G1~G7을 다듬습니다)
- 과제 완료율 80% 이상 (5명 × 3과제 = 15칸 중 12칸 이상)
- 과제 1 소요 90초 이내 (완료한 사람의 평균)
- 평균 만족도 4 이상
