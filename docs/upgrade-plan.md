## 2. 제품 명세 (write-spec)

**문제**: AI 서비스를 만드는 비보안 담당자(기획자·개발자·공정 엔지니어)는 "우리 구조에서 어디가 위험하고 무엇부터 고칠지" 알 방법이 없습니다. 보안 전문가 컨설팅은 비싸고 느립니다.

**목표**
1. 처음 쓰는 사람이 60초 안에 자기 서비스의 1순위 위험과 1순위 대응을 본다.
2. 결과를 "행동 계획"(대응 순서와 예상 점수)으로 받는다.
3. 한 화면이 서비스의 정체성(공정 도면 + 위험 표지)을 가진다.
4. 모든 판정은 AI 호출 없이 브라우저에서 재현된다(무료·비공개 유지).
5. 규칙과 평가 수치는 확장 후에도 정직하게 공개한다.

**비목표**: 실시간 취약점 스캔, 로그인·서버 저장, AI 모델로 위협 생성, 법적 인증 대체, 모바일 앱.

**사용자 이야기**
- 기획자로서, 질문 8개에 답하면 구조가 자동으로 그려지길 원한다. 그래야 그리는 법을 몰라도 시작한다.
- 개발자로서, 가장 효과 큰 대응 3개를 순서대로 보고 싶다. 그래야 이번 주에 무엇을 할지 정한다.
- 공정 엔지니어로서, 센서·PLC 구간의 위험이 설비 쪽 위험으로 따로 보이길 원한다.
- 심사자로서, 근거와 평가 수치를 한눈에 확인하고 싶다.
- 팀 리더로서, 한 장짜리 보고서를 팀에 공유하고 싶다.

## 3. 디자인 계획 (frontend-design)

### 3.1 정체성
소재에서 가져옵니다. 화공 엔지니어에게 가장 익숙한 보안 그림은 **공정 배관계장도(P&ID)**이고 가장 익숙한 경고는 **화학물질 위험 표지(마름모를 4칸으로 나눈 표지)**입니다. ThreatLens의 구조도는 곧 AI 서비스의 배관계장도이므로 이 두 가지를 정체성으로 삼습니다. 제품 전체에서 기억에 남을 요소는 하나만 둡니다: **위험 마름모**.

기본값 회피 검토(frontend-design 점검표)
- 어두운 배경 + 단일 하늘색 포인트 → 폐기. 기본은 밝은 "도면지", 어두운 "제어실" 테마는 선택.
- 똑같은 둥근 카드 + 같은 그림자 → 폐기. 카드는 위계에 따라 3종(1순위 카드, 일반 줄, 접힌 줄)으로 다르게.
- 대문자 라벨, 가운데점 연결, 모노스페이스 소형 라벨 → 쓰지 않음. 단, 규칙·부품 번호(R-01, T-03)는 배관계장도의 "태그 번호"라는 실제 어휘이므로 한 곳(태그)에만 모노스페이스 사용.

### 3.3 부품 기호 (배관계장도 문법)
| 종류 | 기호 | 설명 |
|---|---|---|
| 사용자·사람 | 원 + 사람 | 계기 말풍선 |
| 입력(웹·문서) | 평행사변형 | 흐름도 입력 기호 |

| 저장소 | 원통 | 탱크·저장 |
| 외부 도구 | 마름모 | 밸브 기호 |
| 외부 수신자 | 점선 사각형 | 경계 밖 |
| 센서·설비 | 원, 두꺼운 사각형 | 센서·PLC |

간선은 배관선처럼 직각 꺾임, 위험 경로는 붉은 선 위로 점이 흐르는 애니메이션(움직임은 사용자가 위협 카드를 눌렀을 때만, 감소 모션 설정 존중).

### 3.4 레이아웃

```
┌────────────────────────────────────────────────────────────────────┐
│ ThreatLens   [도면] [규칙] [보고서] [평가]            ◆ 위험 마름모 51 │
├──────┬─────────────────────────────────────────┬───────────────────┤
│부품  │  도면 시트 (모눈 + 신뢰 경계 점선)         │ [행동 계획][위협][점검]│
│아이콘│                                         │ 1순위: 외부 문서 …   │
│목록  │   ▱─▶ ▣AI ─▶ ◇─▶ ┆ ▭                  │  이 2개 적용 → 51→24 │
│      │                          ┌───────────┐   │  [한 번에 적용]       │
│      │                          │표제란     │   │  ────────────────   │
├──────┴──────────────────────────┴───────────┴───┴───────────────────┤
│ 상태줄: "메일 비서 예시를 불러왔습니다. 되돌리기 Ctrl+Z"                 │
└────────────────────────────────────────────────────────────────────┘
```
- 표제란(우하단): 구조 이름, 작성일, 점수. 도면이 곧 보고서 첫 장이 되도록 내보내기에 그대로 사용.
- 오른쪽 패널은 탭 3개: 행동 계획(기본), 위협, 구조 점검.
- 정렬: 좌측 정렬. 가운데 정렬은 빈 화면 안내에만.

### 3.5 문구 원칙 (ux-copy)
- 이름을 한 가지로 고정: "대응"(대응책 X), "부품", "화살표", "되돌리기". 한 동작은 흐름 전체에서 같은 이름.
- 버튼은 동작을 말함: "대응 2개 적용", "예시로 시작", "질문으로 구조 만들기".
- 빈 화면: 무엇인지 + 왜 비었는지 + 시작법. 예) "아직 부품이 없습니다. 질문 8개에 답하면 구조가 자동으로 그려집니다."
- 오류와 실패: 무엇이 + 왜 + 어떻게. 예) "화살표를 놓은 곳에 부품이 없습니다. 다른 부품 위에 놓아 주세요."
- 위협은 3줄 시나리오: "공격자가 → AI가 → 그 결과". 전문 용어는 괄호 안에만.

## 4. 단계별 계획

각 단계 공통 종료 조건: lint·타입·단위·e2e·접근성(axe) 통과 → 푸시 → CI·배포 성공 확인 → 보고. 이 조건을 못 지키면 다음 단계로 가지 않습니다.

### G0. 시안 확정 (디자인 먼저)
- 작업: 3.2~3.4를 시안으로 만든다. Figma 연결을 먼저 시도하고(디자인은 Figma/Canva 우선 원칙), 안 되면 Canva, 둘 다 안 되면 기존 디자인 아티팩트를 갱신한다.
- 산출물: 밝은/어두운 시안 각 1장(편집기), 표제란과 위험 마름모 확대본.
- 통과 기준: 3.1의 기본값 회피 점검 6항목을 통과하고, 색 대비 표가 그대로 지켜짐.

### G1. 디자인 시스템 + 첫인상 (A1~A4)
1. 토큰 교체: 하드코딩 색 0, 글자 5단계, 반지름 2종. 밝은/어두운 테마 전환(기본 밝음, 선택은 저장).
2. 컴포넌트 상태 완성: 버튼(기본·hover·pressed·disabled·loading), 입력, 선택 상자, 탭.
3. 부품 기호 7종 SVG, 도면 모눈 배경, 표제란.
4. 알림은 하단 상태줄로 이동. 예시·불러오기 직후 화면 자동 맞춤(fitView).
- 수락 기준: Given 예시를 불러오면 When 화면이 열리면 Then 모든 부품이 화면 안에 있고 알림이 부품을 가리지 않는다.
- 검사: 화면 캡처 비교(Playwright toHaveScreenshot, 밝음/어두움 × 3폭), 대비 계산 스크립트를 테스트로 고정, axe.

### G2. 행동 계획 (B1, B2) — 핵심 기능
1. `planActions(graph, rules)`: 적용 가능한 대응 전체를 후보로, 점수식(잔여 비율 하한 10%)을 그대로 써서 "다음 한 개"를 탐욕으로 반복 선택(효과/난이도 순). 상위 3개와 누적 점수를 반환.
2. 난이도는 규칙 JSON의 `effort`(low/mid/high) 필드로 사람이 지정(28개 × 대응).
3. UI: "행동 계획" 탭 — 1순위 위험 카드(크게), 대응 3개 체크 목록, "51 → 24" 미리보기, [대응 3개 적용] 한 번에.
- 수락 기준: Given 메일 비서 예시일 때 When 행동 계획을 열면 Then 상위 3개 대응과 각 단계의 누적 점수가 보이고, 적용하면 점수가 표시값과 같게 내려간다.
- 검사: 단위 테스트(단조성: 단계마다 점수 비증가, 계획 점수 = 실제 적용 점수), 탐욕 결과가 소규모 구조에서 전수 탐색의 최적과 얼마나 다른지 비교표로 공개.

### G3. 공격 시나리오와 캔버스 연동 (B3, B4)
1. 규칙 28개에 `story`(공격자→AI→결과 3줄) 추가, 사람이 작성하고 근거 링크와 대조.
2. 위험 마름모(주입·유출·오용·설비 4칸, 칸당 0~4)를 헤더에 표시. 숫자는 해당 범주 규칙의 심각도 합으로 계산(식은 문서화).
3. 위협 카드를 누르면 관련 부품에 번호 배지(①②③), 경로는 붉은 선과 점의 흐름, 나머지는 흐리게. 감소 모션이면 정지 상태로.
- 수락 기준: Given 위협 카드를 눌렀을 때 Then 그 경로의 부품에만 번호가 붙고 마름모의 해당 칸이 강조된다.
- 검사: dataviz 검증기를 테스트에 포함(색 4개 통과 유지), 마름모 값 계산 단위 테스트, 텍스트 대안(표) 제공.

### G4. 질문으로 구조 만들기 (C1, C2)
1. 질문 8개(예: 누가 쓰나요? 외부 파일·웹을 읽나요? 고객 정보에 접근하나요? 메일·API로 밖에 보내나요? 코드를 실행하나요? 사람이 승인하나요? 설비에 연결되나요? 안전 장치가 따로 있나요?)
2. 답 → 부품·화살표·속성을 자동 생성하는 규칙표(JSON). AI 없음.
3. 마지막 화면에서 "도면 열기"로 캔버스에 배치, 이후 자유 편집.
- 수락 기준: Given 8개 질문에 답하면 Then 60초 이내에 점수와 행동 계획이 나온다.
- 검사: 질문 조합 256가지를 전수로 돌려 구조가 항상 유효(AI 부품 1개 이상, 끊긴 부품 없음)함을 단위 테스트로 보장.

### G5. 구조 점검 (C3)
- 경고 규칙: 입력 없는 AI, 이어지지 않은 부품, AI와 도구가 직접 안 이어짐, 방향이 뒤집힌 듯한 화살표(도구→AI인데 도구가 입력 부품일 때).
- UI: 오른쪽 "점검" 탭과 해당 부품에 노란 배지.
- 검사: 단위 테스트(경고별 양·음성 사례).

### G6. 깊이 확장 (D1, D3)
1. 부품 +6: 벡터 DB, 플러그인, 승인 게이트, 모델 서버, 사내 위키, 설비 알람.
2. 속성 +4(예: 출처 표시, 출력 필터, 속도 제한, 감사 로그), 규칙 28→40 (근거 공개 표준에서 직접 매핑; OWASP LLM 2025, ATT&CK for ICS, CISA).
3. 신뢰 경계: 도면 위에 "사내/사외" 점선 영역을 그리고, 경계를 넘는 화살표에 자동 표시. 규칙이 경계 정보를 조건으로 사용.
4. 평가표 재실행: 정답표는 그대로 두고(독립 작성 유지) 전후 수치를 공개. 새 규칙이 정답표 밖이면 "정답표 확장 필요"로 분리해 적는다.
- 검사: 규칙 스키마 검증(근거 필수), 평가 수치가 기존보다 나빠지지 않을 것.

### G7. 보고서 v2 (B5)
- 첫 장: 표제란이 있는 도면 SVG, 위험 마름모, 한 문단 요약.
- 둘째 장: 행동 계획 표(순서, 대응, 난이도, 예상 점수).
- 이후: 위협 상세(시나리오 3줄 + 근거), 한계 고지.
- 인쇄: A4 한 장 요약 + 상세, Markdown 내보내기 유지.
- 검사: 인쇄 CSS 캡처, 링크 유효성(근거 URL 형식).

### G8. 사용자 검증 (user-research) — 사람이 하는 단계
- 방법: 사용성 테스트 5명(주변 동기·가족 포함 가능). 한 명당 15분.
- 진행: 환영 2분 → 과제 3개(예시 없이 질문으로 구조 만들기 / 가장 큰 위험 말하기 / 대응 적용해 점수 낮추기) → 소감 5분.
- 기록: 막힌 곳 위치, 걸린 시간, "이게 무슨 뜻인지 모르겠다" 횟수, 한 줄 만족도(1~5).
- 목표: 과제 완료율 80% 이상, 과제 1 소요 90초 이내, 평균 만족도 4 이상.
- 제가 준비: 진행 스크립트, 기록표, 결과 집계 양식. 사람이 해야 할 일: 5명 섭외와 관찰. 결과를 받으면 G1~G7을 다듬습니다.
