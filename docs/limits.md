## 1. 해결한 한계

| 한계 | 해결 방법 | 확인 방법 |
|---|---|---|
| 시나리오·위험 성격·난이도를 AI가 혼자 정함 | ① 규칙 데이터 일관성 자동 시험 143개(조건→위험 성격 유도, 시나리오가 조건을 모두 언급, 같은 대응=같은 난이도, 점수 범위 등) ② 작성자와 별개의 검수 에이전트가 28개 규칙 전체를 검토 → 지적 반영(아래 2) | `src/domain/rules-consistency.test.ts` |

| 난이도 반영이 실제로 효과가 있는지 모름 | 난이도를 무시했을 때와 비교: 5개 중 4개에서 2·3번째 추천이 달라지고, 난이도 반영으로 잃는 점수는 0~2점 | 같은 시험 파일 |

## 2. 독립 검수 결과와 반영

검수자는 규칙 파일을 쓰지 않은 별도 에이전트입니다(전문가가 아니라 AI이므로, 아래 "사람이 해야 하는 일"을 대체하지 않습니다).

**반영함**
- 과장 문구 완화: R-03(시스템 전체→연쇄적 변경), R-07, R-17, R-18(가장 넓습니다→넓습니다)
- 조건으로 알 수 없는 전제를 문장에서 "~라면"으로 조건화: R-14, R-16, R-19, R-20, R-23, R-26(1행)
- 점수 과대 조정: R-01·R-14 출처 구분, R-03 샌드박스, R-09·R-13 범위 검사(난이도 보통으로), R-14 출력 필터, R-20 업체 옵션, R-22 수신자 허용 목록, R-25(승인 -20, 샌드박스 -30)
- 대응 교체·추가: R-23 `쓰기 시 권한 구분` → `검색 시 질문자 권한으로 거르기`, 설비 규칙에 `AI는 권고만 하고 제어 쓰기 경로 제거`(R-10·R-12·R-13), `중복 센서·물리 모델과 교차 검증`(R-09), R-13에 담당자 확인
- 근거 정정: R-27 근거를 LLM03 → LLM05(출력 처리)로, R-06에서 주제가 어긋난 ATLAS T0057 제거
- 겹치는 대응의 합이 커지지 않도록 설비 규칙 대응 점수 합을 90 이하로 조정(기존 시험이 요구)

**반영하지 않음 (구조 변경이 필요하거나 판단이 갈림)**

| 지적 | 이유 / 상태 |
|---|---|
| `human.approval` 속성 하나를 모든 승인 대응이 공유(저장소 검수가 설비 승인을 대신함) | 속성 분리는 엔진·화면·평가표 전체 변경. 한계로 남김. 평가표 정답과 함께 G6에서 재검토 |
| 대응 점수 단순 합산(겹침 과대평가) | 이미 하한 10%와 규칙별 합 상한 시험이 있음. 화면에 "추정치" 표시는 G7 보고서에 추가 예정 |
| 포함 관계 규칙(R-01⊂R-02 등) 이중 계산 | 점수는 위협별 위험을 곱으로 합쳐 이미 포화됨. 접기(`supersedes`)는 G6 후보 |
| R-26 심각도 낮추기 | 평가표 결과가 바뀜. 사람 검토 항목으로 이관 |
| 대응이 `when` 조건을 지우지 못함(`sets`만 있음) | 의도한 설계: 점수는 낮추지만 위협은 계속 표시함(남은 위험 10% 하한) |
| `memory.recall`, `store.per_user` 속성 추가 | G6(속성 +4) 후보 |
| MITRE ATLAS 번호·ATT&CK for ICS 번호 일부, CISA 지침 원문, IEC 61511 원문 | 검수자와 작성자 모두 원문 확인 불가. 아래 사람 확인 항목 |

## 3. 가중치 민감도 결과

예시 5개(문서 질의응답 / 고객지원 / 코드 에이전트 / 메일 비서 / 공정) 점수:

| 흔든 값 | 예시 5개 점수 | 결과 |
|---|---|---|
| 기준 | 25 / 63 / 61 / 51 / 43 | - |
| 심각도 전체 ×0.7 | 18 / 50 / 48 / 38 / 32 | 같음 |
| 심각도 전체 ×0.85 | 22 / 57 / 55 / 45 / 38 | 같음 |
| 심각도 전체 ×1.15 | 29 / 69 / 66 / 56 / 48 | 같음 |
| 심각도 전체 ×1.3 | 32 / 73 / 71 / 61 / 53 | 같음 |
| high ×0.7 | 25 / 57 / 52 / 42 / 33 | 같음 |
| high ×1.3 | 25 / 69 / 69 / 58 / 51 | 같음 |
| medium ×0.7 | 18 / 57 / 57 / 47 / 42 | 같음 |
| medium ×1.3 | 32 / 69 / 64 / 54 / 44 | 같음 |
| low ×0.7 | 25 / 63 / 61 / 51 / 43 | 같음 |
| low ×1.3 | 25 / 63 / 61 / 51 / 43 | 같음 |
| 난이도 1/1/1 (무시) | 계획이 달라진 예시 4/5, 난이도 반영의 점수 손해 1/2/0/2/0점 | - |
| 난이도 1/1.5/2 | 첫 추천 5/5 동일 | - |
| 난이도 1/3/5 | 첫 추천 5/5 동일 | - |

읽는 법: 어떤 가중치를 흔들어도 예시들의 위험 **순서**는 같습니다. 숫자 자체는 바뀝니다(예: 심각도 전체 ×1.3이면 메일 비서 51→61). 그래서 점수는 "절대 확률"이 아니라 "구조끼리 비교하는 지표"로만 설명합니다.

## 4. 사람이 해야 하는 일 (AI가 대신할 수 없음)

| # | 할 일 | 방법 | 통과 기준 |
|---|---|---|---|
| H1 | 규칙 28개의 전문가 검토 | AI 보안 또는 화공 안전 전문가 1명에게 `docs/rules.md`를 보여주고 규칙별 맞음/틀림/과장 표시 | 틀림 0개, 과장은 문구 수정 |
| H2 | 평가표 정답 사람 검수 | 정답을 쓴 것도 AI이므로, 사람이 예시 5개 정답을 독립적으로 다시 판정하고 일치율 계산 | 일치율을 평가표에 함께 공개 |
| H3 | 실제 스크린리더 시험 | NVDA(Windows) 또는 VoiceOver(Mac)로 ①예시 불러오기 ②위협 카드 펼치기 ③대응 적용 ④평가표 읽기 | 각 과정을 소리만으로 끝낼 수 있음 |
| H4 | 사용자 시험 5명(G8) | 첫 화면부터 "행동 계획 3개 확인"까지 60초 안에 가능한지 관찰 | 4/5 이상 성공 |
| H5 | 외부 출처 원문 확인 | CISA AI-OT 지침, ATT&CK for ICS 번호, ATLAS 번호를 원문 사이트에서 열어 보고 `ref` 일치 확인 | 불일치 0개 |

## 5. 출처 표기

- 규칙 문구·시나리오·난이도·대응 점수·평가표 정답은 AI가 작성했고 사람 검수 전 상태입니다(H1·H2 완료 시 갱신).
- 점수는 추정치이며 실제 사고 확률이 아닙니다.
