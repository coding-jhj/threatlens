# F2 점검 보고서: 접근성 · 반응형 · 성능

점검일 2026-10-03. 방법: 계산 스크립트, Playwright(Chromium) 실측, vitest. 모두 `npm run e2e`, `npm test`로 다시 돌릴 수 있습니다.

## 1. 명암비 (WCAG 2.x AA, 글자 4.5:1)

가장 어두운 면(`--selected-bg`)과 가장 밝은 면(`--bg`) 기준 최저값입니다.

| 글자색 | 최저 비율 | 판정 |
|---|---|---|
| `--text` | 12.67 | 통과 |
| `--muted` | 6.74 | 통과 |
| `--accent` | 6.89 | 통과 |
| `--red` / `--coral` | 5.30 / 5.48 | 통과 |
| `--amber` / `--green` / `--purple` | 8.40 / 7.68 / 6.45 | 통과 |
| 칩 글자 on 칩 배경 (red, amber, green, purple) | 5.65 / 7.72 / 6.81 / 6.31 | 통과 |
| `--accent-ink` on `--accent` (기본 버튼) | 8.90 | 통과 |

참고: 테두리(`--line`)는 배경 대비 1.55:1입니다. 장식용 구분선이라 기준 밖이지만, 입력 칸 테두리로는 약합니다 (한계로 기록).

## 2. 키보드

| 항목 | 결과 |
|---|---|
| Tab 순서 (메뉴 → 부품 → 예시 → 캔버스 도구 → 위협 카드) | 통과, 40단계 모두 포커스 링 표시 |
| 부품 추가 (Enter) | 통과 |
| 캔버스 부품에 포커스 + Enter → 속성 창 | 통과 (React Flow 기본 기능) |
| 되돌리기 Ctrl+Z | 통과 |
| 안내 창 Esc | 통과 |
| 안내 창 포커스 이동·가둠·복귀 | **수정**: 열어도 포커스가 창 밖에 있었음 → 창 안으로 이동, Tab 순환, 닫으면 눌렀던 버튼으로 복귀 |
| 예시·저장 메뉴 Esc | **수정**: 닫히지 않았음 → Esc로 닫힘 |
| 화살표 잇기 | **수정**: 마우스로만 가능했음 → 부품 선택 후 속성 창의 "키보드로 잇기" 목록에서 대상 선택 + "화살표 추가" |

## 3. 반응형

## 4. 성능 (부품 100개)

| 측정 | 결과 | 기준 |
|---|---|---|
| 분석+점수, 100개·연결 200개 | 약 13~17ms | 1초 |
| 분석+점수, 100개·연결 1,590개 (경로 폭증형) | 약 4ms (경로 상한 500이 작동) | 1초 |
| 화면에 부품 100개 놓은 뒤 프레임 2개 | 약 15ms | 100ms |

참고: 저장·불러오기·공유 링크는 60개까지만 받습니다(`MAX_NODES`). 100개는 직접 그릴 때만 가능한 상태입니다.

## 5. 남은 한계

- 화면낭독기(NVDA 등)로는 확인하지 못했습니다. 포커스 이동과 이름표(aria-label)만 자동 검사했습니다.
- 캔버스 위 화살표 선택·삭제의 키보드 경로는 React Flow 기본 동작에 맡겼고 별도 검증하지 않았습니다.
- 모바일(폭 600px 이하)은 범위 밖입니다. 노트북·태블릿만 지원합니다.
- 입력 칸 테두리 대비 3:1 미달 (위 1번 참고).
